# 毎日のジャーナルアプリ 仕様書

## 概要

ますださんの外部拡張脳として機能する、日々のジャーナル＋タスク管理アプリ。Geminiのチャットスレッドでの「脳内ノイズ投下 → AI整理 → 物理的動線出力」運用を、構造化されたアプリ体験に落とし込んだもの。

**プロダクト方針：個人特化 → 一般配布を検討中（未決着）**
長らく「個人特化で確定」（企業向け展開＝認証・マルチユーザー・サーバDB・権限管理は不採用）としてきたが、
v0.11時点で **Playストアでの一般配布** を検討し始めた。方針は揺れており未確定。

配布する場合の最大の障壁は **AI推論の経路**：
- ローカルLLM完結（現行の既定）は、他人のAndroid端末に localhost のLLMが無いため**成立しない**
- 自前サーバ運営はコスト面でユーザーが否定的
- 残る選択肢は **BYOK**（各自でエンドポイント/キー設定＝上級者向け）か **オンデバイス小型LLM**（方針一貫だが実装ハードル高）

この決着前に配布向けUI設計を進めないこと。

## ユーザープロトコル（最重要）

ますださんは本アプリを「外部前頭葉」として使用する。以下4フェーズで運用される。

### フェーズ1：入力（生データの無加工ダンプ）
- 疲労・眠気状態でも脳内ノイズをそのままテキスト化
- ビジョン・タスク・家事・趣味を整理せず羅列

### フェーズ2：処理委任（実行機能の外部化）
- タスクの取捨選択をAIに任せる
- MECEに整理させる
- 「今日やるべき」「今日はやってはいけない」を判断させる

### フェーズ3：エラーログ解析【専用機能は撤去・人格として継承】
- 「寝落ちした」「甘いもの食べた」「風呂に入らなかった」を**バグ報告**として提出
- **生理学的・物理学的な原因解析**を求める（慰めは不要）
- 翌日の対策データとして利用
- ※v0.11で専用タブとして一度実装したが、UIが重く一般配布に向かないと判断し**撤去**。
  代わりに AIチャットの **🔥 スパルタ人格**（`PERSONAS.spartan`）がこの役割を継承している。
  厳しい原因究明はチャットで対話的に行う形に集約された。

### フェーズ4：アクション出力（物理的動線）
- 精神論禁止
- 「帰宅したら座らずに浴室へ直行」のような摩擦ゼロの物理動線
- 「PCの電源を入れない」など**禁止事項**も含む

## タブ構成

メインタブは5つ（v0.9でToDoを独立タブに昇格）。

### ✏️ 記録タブ
1. 日付選択
2. **🧠 ダンプモード**（折りたたみ・設定でオフ可）
3. **🎯 目標セクション**（折りたたみ）
4. ジャーナルフィールド（感謝・今日の目標・明日の目標・ひとこと／設定で各項目の表示切替可）
5. 保存ボタン＋AI会話ボタン

### 📅 予定タブ
- スケジュール生成のみ（旧サブタブ構成は撤去）

### ✅ ToDoタブ（独立メインタブ）
- グルーピング表示・期限管理・AI自動抽出・インライン編集

### 🔁 ルーチンタブ
- サブタブ：**チェック** / **達成率** / **導入中** / **導入済**

### 🤖 AIタブ
- サブタブ：**チャット** / **傾向** / **目標** / **履歴**

### ⚙️ 設定
- 入口はヘッダー右上の控えめな⚙️に一本化（誤タップ抑制・低頻度機能の定位置）。
- 下からせり出すボトムシート1画面。セクション見出しで整理。

## 機能詳細

### ダンプモード
- 大きなテキストエリアに脳内ノイズを投下
- 「✨ AIで整理する」押下で：
  - ダンプ本文だけを各ジャーナルフィールドに自動振り分け。AIは既存内容を重複回避の参考として読み、新しく足す差分だけを返す
  - 稼働シーケンス生成（物理動線ベース）
  - **自動保存**＋「✅しっかり保存されました」トースト（秒数は設定で可変・タップで消去）
  - AIによるToDo自動抽出も同時実行（設定でオフ可）
- 差分と既存フィールドの結合はアプリ側で行う。差分が空なら既存のまま、既存が空なら差分を採用、既存が差分を含むなら既存のまま、それ以外は既存＋`,`＋差分とする。AI出力で既存内容を置き換えない
- 整理に成功したダンプ本文とダンプ欄が同じ内容の間は「✨ AIで整理する」を無効化し、本文を書き換えると再び有効化する
- ダンプ元テキストはジャーナルには保存しないが、整理後もダンプ欄から自動クリアしない
- **設定でダンプモード全体を非表示にできる**（オフ時は稼働シーケンスの生成手段も消える。閲覧は履歴タブで可）

### 稼働シーケンス
- 配列形式の箇条書きチェックリスト
- 各行を独立して✓できる
- 右下に「n / n 完了」カウンタ
- 再生成時はチェック状態リセット（上書き方式）
- 履歴タブから過去分も閲覧可能
- ダンプモード内に固定配置

### 目標管理
- **大目標・中目標・近目標**の3レイヤー
- 最新の1セットのみ保持（履歴なし、上書き）
- 全AI機能のプロンプトに埋め込まれる
- 折りたたみ時は内容のサマリーを表示

### ジャーナルフィールド
- 🙏 今日ありがたいこと / ✅ 今日の目標 / 🔜 明日の目標 / 💬 ひとこと（その他の受け皿）
- 設定で各フィールドの表示／非表示を切替可能
- **手入力の消失防止**：編集後の自動保存（debounce）＋日付切替時フラッシュ＋リロード時localStorage保存

### スケジュール生成
- 複数の**ベーススケジュール**を作成・切替可能（折りたたみ表示）
- 各ブロックに🔒固定 / 🔓可変フラグ
- AIは固定ブロックを守りつつ、可変ブロックを今日の目標と未完了ToDoに合わせて調整
- 備考フィールドはAIへの補足指示として使われる
- ベース未選択時は生成ボタン無効（先にベース作成が必要）

### ToDo
- グルーピング表示：⚠️期限切れ / 🔥今日 / 📅明日 / 📆今週 / 🔮未来 / 📋期限未設定
- 期限クイック選択：今日・明日・3日後・1週間後・日付指定・クリア
- ソースラベル：手動 / 今日の目標 / 明日の目標
- テキストタップでインライン編集（Enter確定・Escキャンセル）
- AI自動抽出：日記保存/ダンプ整理時に「今日/明日の目標」から抽出（設定で各オフ可）
- 完了済みは下部に分離、まとめて削除可能

### ルーチン（v0.10で大幅拡張）
- 導入中・導入済の2カテゴリ（上限は設定で可変、既定25個）
- 相互に移動可能
- **スケジュール指定**：毎日 / 曜日指定（複数曜日）/ 間隔指定（n日ごと・起点日）
- チェック画面は**その日が対象のルーチンだけ表示**（対象なしの日は専用メッセージ）
- 各ルーチンに頻度バッジ、タップでスケジュール編集モーダル
- 達成率分析：**対象日のみを分母**に算出。短期/長期の集計期間は設定で可変。日別棒グラフ（対象0の日は除外＝グレー）、ルーチン別ランキング（達成/対象日数）
- ルーチン削除時、チェック履歴の該当idも掃除

### AI機能
- **チャット**：当日エントリ＋**未完了ToDo・本日のルーチン達成・本日のスケジュール**を読んだ上で自由会話（多ターン）
  - **人格切替（v0.11）**：🔥 スパルタ（既定）/ 🙂 ノーマル / 💕 恋人。設定のAI接続セクションで選択。
  - スパルタ＝プロトコル3の継承。慰め・お世辞なし、生理学的/物理学的な原因究明、対策は物理動線、精神論禁止（ただし罵倒・人格否定はしない）。
  - **チャットのみに適用**。傾向・目標の分析はトーンを乗せると指摘が甘くなるため、意図的にフラットのまま。
- **傾向**：直近7件の日記と、大中近の目標・未完了ToDo・ルーチン達成率を使った分析
- **目標**：大中近目標と直近14日の行動＋**未完了ToDo・ルーチン達成率**のギャップ分析
- **履歴**：日付ごとの記録一覧、各日の編集・AI会話呼出・稼働シーケンス確認

### 設定画面（v0.9〜大幅拡張）
**AI接続**
- モード切替：🖥 ローカル / ☁️ クラウド（既定ローカル）
- ローカル：OpenAI互換エンドポイント（Ollama/LM Studio/llama.cpp）・モデル名・temperature
- クラウド：モデル名（日記が外部送信される旨の警告表示）
- **チャットの人格**：🔥 スパルタ（既定）/ 🙂 ノーマル / 💕 恋人

**表示・動作**
- アプリ名・サブタイトルのカスタム
- 起動時に開くタブ
- 起動時の日付（常に今日 / 最後に開いた日）
- 保存トーストの表示秒数
- ダンプモードの表示ON/OFF
- ジャーナル各項目の表示／非表示
- ダンプ整理後／日記保存時のToDo自動抽出ON/OFF
- ルーチン1タブの上限
- 達成率グラフの集計期間（短期・長期）
- データ保持の上限（日記日数・完了ToDo件数・ルーチンチェック日数）

**データ管理**
- エクスポート（全データJSON）/ インポート（型検証付き）/ 🧹 古いデータ整理

**アプリ情報**
- バージョン・各種件数・上限表示

**⚠️ 危険ゾーン**
- 種別ごとの削除（日記・ToDo・ルーチン・生成予定）
- 全データリセット（confirm二段）

## データ構造

### ストレージキー（window.storage + localStorage の二重保存）
LS_PREFIX: `journal_v1_`

| キー | 型 | 内容 |
|---|---|---|
| `journal-entries` | `{date: EntryObj}` | 日記エントリ |
| `goals` | `{bigGoal, midGoal, nearGoal}` | 目標3レイヤー |
| `base-schedule-list` | `BaseSchedule[]` | ベーススケジュール一覧 |
| `active-base-id` | `string` | 現在選択中のベースID |
| `generated-schedules` | `{date: Block[]}` | AI生成スケジュール |
| `routines` | `{active: Routine[], done: Routine[]}` | ルーチン（オブジェクト化） |
| `routine-checks` | `{date: {routineId: bool}}` | チェック履歴（idキー） |
| `todos` | `TodoObj[]` | ToDo一覧 |
| `ai-config` | `AiConfig` | AI接続設定 |
| `app-settings` | `Settings` | アプリ動作設定 |
| `last-date` | `string` | 「最後に開いた日」モード用 |

### EntryObj
```
{
  grateful: string,
  todayGoal: string,
  tomorrowGoal: string,
  memo: string
}
```
※ 旧 `sequence` / `sequenceChecks` は廃止（v0.12）。「今日の稼働シーケンス」は
ToDoから導出する派生ビューになり、実行タスクのデータは `todos` に一元化された。
既存エントリに残る旧キーは読み飛ばされる（削除はしない）。

### 今日の稼働シーケンス（派生ビュー・保存しない）
`buildTodaySequence(todos, today)` が `todos` から算出する。
- 対象：`dueDate <= today` のToDo
- `carried`（`dueDate < today` の繰り越し）と `today` に分けて表示
- 並び順は配列の格納順＝AIが提案した実行順（朝→夜の物理動線）
- チェックすると実体のToDoが `done: true` になる
- 記録タブのダンプモードの「上」に配置。既定は折りたたみで、ダンプ整理の直後に自動展開

### TodoObj
```
{
  id: string,                    // uid()生成（crypto.randomUUID）
  text: string,
  done: bool,
  source: "manual" | "ai-today" | "ai-tomorrow",
  createdAt: "YYYY-MM-DD",
  dueDate: "YYYY-MM-DD" | null
}
```

### Routine（v0.10：文字列→オブジェクト化）
```
{
  id: string,
  text: string,
  schedule: Schedule
}
```

### Schedule
```
{ type: "daily" }
{ type: "weekly", days: number[] }        // 0=日〜6=土
{ type: "interval", interval: number, anchor: "YYYY-MM-DD" }
```
- 旧形式（文字列のルーチン）は読み込み時に `normalizeRoutines()` で `{type:"daily"}` へ自動変換。

### BaseSchedule
```
{
  id: string,
  name: string,
  note: string,                  // AIへの補足指示としても機能
  blocks: [{ id, time: "HH:MM", label, fixed: bool }]
}
```

### 生成されたScheduleのBlock
```
{ time: "HH:MM", label: string, note: string, fixed: bool }
```

### AiConfig
```
{
  mode: "local" | "cloud",
  localEndpoint: string,         // 既定 "http://localhost:11434/v1"
  localModel: string,            // 既定 "qwen2.5"
  cloudModel: string,            // 既定 "claude-sonnet-5"
  temperature: number,           // ローカル生成の温度（既定0.7）
  persona: "spartan" | "normal" | "lover"  // チャット人格（既定 "spartan"）
}
```

### Settings
```
{
  appTitle, appSubtitle,
  defaultTab, startDateMode,     // "today" | "last"
  showDumpMode, toastSeconds,
  // 表示するジャーナル項目（順序込み・設定画面で編集可）。旧 hiddenFields は自動移行される。
  // todayGoal / tomorrowGoal は ToDo抽出・予定生成の入力源のため削除不可（ラベル変更と並替のみ）。
  journalFields: { key, label, placeholder, rows, core }[],
  autoExtractOnDump, autoExtractOnSave,
  limitEntriesDays, limitDoneTodos, limitRoutineCheckDays,
  limitRoutinePerTab,
  statsShortDays, statsLongDays
}
```

## 件数制限（自動プルーニング）

保存処理のタイミングで自動実行。上限は設定で可変（既定値は下記）。

| データ | 既定上限 | 削除ルール |
|---|---|---|
| 日記エントリ | 730日（2年） | 古い日付から |
| 完了済ToDo | 100件 | 古いcreatedAtから |
| ルーチンチェック | 365日（1年） | 古い日付から |
| ルーチン（導入中・導入済） | 各25個 | 手動削除のみ |

設定画面に「🧹 古いデータを整理」ボタンで手動実行も可能。

## AI仕様

### モデル
- ローカル：OpenAI互換 `/chat/completions`（Ollama/LM Studio/llama.cpp、既定 `qwen2.5`）
- クラウド：Anthropic Messages API（既定 `claude-sonnet-5`）
- JSONを返すダンプ整理・ToDo抽出・スケジュール生成は proxy/local で temperature 0.2 固定。チャットと傾向・目標分析はユーザー設定値（既定0.7）を使い、cloudはtemperatureを送信しない
- `callClaude()` がモードで分岐。HTTPエラーは `res.ok` チェックで明示throw。

### 主要プロンプト
1. `dumpProcess` - ダンプ整理＋稼働シーケンス生成
2. `extractTodos` - 今日/明日の目標からToDo抽出
3. `generateSchedule` - 固定/可変を考慮した日次スケジュール
4. `buildChatSystem` - AIチャットのシステムプロンプト（ToDo・ルーチン・スケジュール含む）
5. `runTrend` - 直近7件の傾向分析
6. `runGoals` - 目標ギャップ分析（ToDo・ルーチン達成率含む）

### 共通ルール
- 出力はJSON。`extractJson()` で前置き文・末尾テキスト・コードフェンス・文字列内括弧に耐えるパース（ローカル小型モデル対策）
- 稼働シーケンスは必ず配列形式
- 精神論を禁止、物理動線を要求

## 決定済み仕様（変更しない）

- 稼働シーケンスは**ダンプモード内**の位置が固定
- 再生成は**上書き**（履歴なし）
- チェックは**各行独立**
- ダンプ元テキストは**保存しない**
- 期限切れToDoは**残す**（自動削除しない）
- ルーチンは**手動削除のみ**
- 古いデータは**要約せず件数制限で対応**
- ToDoは**独立メインタブ**（予定タブのサブタブ構成は撤去）
- 設定入口は**ヘッダー右上⚙️に一本化**
- AIは**ローカル既定**、クラウドは選択式
- ルーチン達成率は**対象日のみ分母**
- チャット人格は**スパルタが既定**（甘いモードはオプト扱い＝尖りを既定に置く）
- 人格は**チャットのみ**に適用（分析系はフラット維持）
