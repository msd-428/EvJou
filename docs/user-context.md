## 保留中の議論

### プライバシー対応 ＆ 配布時のAI推論経路【最大の未決着論点】
**元の方針**：ローカルLLM（Qwen等）で完結。クラウドは選択式（送信警告あり）。
**ステータス**：ローカル切替は実装済み。ただし**Playストア配布との矛盾が露呈**。

他人のAndroid端末に localhost のLLMは存在しないため、ローカル完結は配布時に成立しない。
サーバ運営はコスト面でユーザーが否定的（「APIも私が鯖主は厳しいな」）。残る選択肢：
- **BYOK**：各自でエンドポイント/キー設定。現状のAI設定UIがほぼこれ。上級者向けと割り切る配布。
- **オンデバイス小型LLM**：サーバ不要・「日記が外部に出ない」看板を維持できて方針一貫。実装ハードル高。

**この決着が配布設計の全ての前提。UI設計はその下流。**

### 稼働シーケンスの表示位置
**現状**：ダンプモード内のみ表示
**ユーザー回答**：「そのままの場所で良い」
**ステータス**：現状維持。ただしダンプ非表示設定をオンにするとシーケンス生成手段も消える点に注意（閲覧は履歴）。

## 開発上のトラブル履歴

### データ永続化の不安定性
`window.storage`のみでは消えることがあった→ `localStorage`との二重保存で解決

### パーサエラー頻発
巨大な`update`を連続適用するとパーサエラーが起きる→ `rewrite`で全面書き直しが早い。大改修時はbabelでパース検証＋ヘッドレスrenderで確認すると安全。

### sequence形式の変更
文字列→配列に変更。過去データとの互換性のため`normalizeSequence()`で必ず配列化

### routine形式の変更（v0.10）
文字列→オブジェクト（id/text/schedule）に変更。`normalizeRoutines()`で旧データを自動変換。チェック履歴はtextキー→idキーに刷新（旧checksは破棄前提でユーザー了承済み）。

### タイムゾーンバグ
`new Date().toISOString()`はUTC基準で、JST 00〜09時に日付が前日にずれていた→ `toLocalDateStr()`でローカル日付に統一。

### ローカルLLMのJSON崩れ
小型モデルが前後に地の文を付けてパース失敗→ `extractJson()`で最初のJSON値だけ抽出（文字列内括弧にも対応）。

### アロー関数 vs function
パーサエラー対策で一時`function`構文に統一したが、後に現代的な書き方（アロー関数）に戻した
