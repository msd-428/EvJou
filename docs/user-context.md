- **手入力の自動保存**（debounce＋日付切替フラッシュ＋beforeunload）
- **危険ゾーン**：種別削除・全リセット

### 製品方針 — オフライン優先の段階戦略（2026-07-29 決定）
これは「一生オフラインのみ」という決定では**ない**。フェーズを分ける戦略。

- **フェーズ1（＝現在・当面の最優先）：完全オフラインをデフォルトとする。**
  アカウント不要・データは端末内で完結。まだ製品版としてリリースできる段階ではないため、
  テスト版を新規ユーザーへ広める際の**最初のフック**を
  「アカウント不要ですぐ始められる手軽さ」＋「データがローカル完結する安心感」に置く。
- **フェーズ2（リリース後）：アカウント登録による複数端末間のクラウド同期を、
  あくまで「オプション機能」として提供する構想を持っている。**
  ただし**実装は後回し**。同期を前提にした設計変更・データモデル変更を、
  この段階で先回りして入れないこと（＝YAGNI。ストレージ層は既に抽象化済みなので後から足せる）。
- ※ 上記フェーズ2は**個人ユーザーの端末間同期**の話であり、
  「不採用の決定一覧」にある**企業向け展開（認証・マルチユーザー・サーバDB）とは別物**。混同しないこと。
- ※ AI推論の Firestore プロキシは**リクエストの受け渡しのみ**で日記を保存しない。上記と矛盾しない。

方針・設計思想に反するため**恒久的に不採用**。提案しないこと。

## v1スコープ外（リリース後に再検討可）

**否定された機能ではなく、初期リリース(v1)に含めないと決めたもの。**
v1が出るまでは提案しないが、リリース後に必要性が実データで裏づけられたら検討してよい。

| 案 | v1で見送る理由 | 再検討の目安 |
|---|---|---|
| OS通知・リマインダー（プッシュ通知含む） | v1の価値はオフライン完結の記録＋整理。通知は権限要求・配信基盤・設定UIを伴い、初期リリースのスコープを膨らませる | リリース後、「開き忘れて記録が途切れる」が実際の離脱要因だと分かった場合 |
| 検索機能 | 件数制限下では手で辿れる。v1のデータ量では投資に見合わない | 蓄積が数百日規模になり、履歴を辿る操作が実際に苦になってきたら |
| 古いデータの自動要約 | 件数制限で足りている | 上と同じ。長期運用で件数制限による情報消失が痛くなってきたら |

## 保留中の議論

### プライバシー対応 ＆ 配布時のAI推論経路 → 決着（2026-07-29構想追加）
**元の方針**：ローカルLLM（Qwen等）で完結。
**課題**：他人のスマホにlocalhostは存在しないため、そのままでは配布できない。

**最終方針（リリース後のマネタイズ構想）**：
- 今回実装した「Firestoreプロキシ（開発者のPC/クラウド経由）」のアーキテクチャを商用基盤としてそのまま活用する。
- サーバ代（API代）の課題は、完全有料化ではなく**「フリーミアム（無料枠＋サブスクリプション）」のビジネスモデル**にすることで解決する。
- **無料枠の設計**：「1日あたりの利用回数を厳しく制限する」「サブスク課金ユーザーの処理を優先し、無料ユーザーはキュー（待ち行列）の優先順位を下げてピーク時は待たせる」など、無料ユーザーにも体験させつつ課金への優位性を作る。
（※まずは自分用のオフライン完結版としてv1をリリースし、フェーズ2のクラウド同期等と併せてリリース後に着手する）

### 稼働シーケンスの表示位置 → 決着（2026-07-29）
ダンプモードの**上**に独立配置。既定は折りたたみで、ダンプ整理の直後に自動展開する
（入力に対する報酬としての見せ方）。データはToDoに一元化され、シーケンスは派生ビューになった。
ダンプ非表示設定でもシーケンス自体は残る（ToDoに期限「今日」を付ければ並ぶ）。

## 開発上のトラブル履歴

### データ永続化の不安定性
`window.storage`のみでは消えることがあった→ `localStorage`との二重保存で解決

### パーサエラー頻発
巨大な`update`を連続適用するとパーサエラーが起きる→ `rewrite`で全面書き直しが早い。大改修時はbabelでパース検証＋ヘッドレスrenderで確認すると安全。

### sequence形式の変更 → 最終的に廃止（v0.12）
文字列→配列と変遷し、`normalizeSequence()`で互換吸収していたが、
**稼働シーケンスとToDoでタスクを二重管理していた**ため `form.sequence` ごと廃止。
現在は `buildTodaySequence(todos, today)` がToDoから導出する派生ビュー。旧キーは読み飛ばす。

### routine形式の変更（v0.10）
文字列→オブジェクト（id/text/schedule）に変更。`normalizeRoutines()`で旧データを自動変換。チェック履歴はtextキー→idキーに刷新（旧checksは破棄前提でユーザー了承済み）。

### タイムゾーンバグ
`new Date().toISOString()`はUTC基準で、JST 00〜09時に日付が前日にずれていた→ `toLocalDateStr()`でローカル日付に統一。

### ローカルLLMのJSON崩れ
小型モデルが前後に地の文を付けてパース失敗→ `extractJson()`で最初のJSON値だけ抽出（文字列内括弧にも対応）。

### アロー関数 vs function
パーサエラー対策で一時`function`構文に統一したが、後に現代的な書き方（アロー関数）に戻した
