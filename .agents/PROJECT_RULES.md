# EvJou 共通ルール（全エージェント共通の正典）

このファイルは Claude Code・Codex・Antigravity が共有するルールの**唯一の出典**です。
ツールごとの入口ファイルは薄く、ここへの参照と役割差分だけを持ちます。

- `CLAUDE.md` — Claude Code の入口
- `AGENTS.md`（リポジトリルート）— Codex の入口
- `.agents/AGENTS.md` — Antigravity（IDE側エージェント）の入口

**入口ファイルにこのファイルの内容を複製しないでください。**
同じことを二度書くと、必ずどちらか片方が古くなります。

**例外条項はこの正典側にだけ置きます。** 入口ファイルには禁止だけを書き、
「例外は `PROJECT_RULES.md` §N にある」と参照させます。
禁止を入口に複製すると、正典側だけを例外化した指示書が出たときに入口と矛盾し、
それを受け取ったセッションが着手前に停止します。**その停止は正しい振る舞いであり、
指示を出した側の設計ミスです。**

## 最初に読む順番

1. 使用中のツールに対応する入口ファイル（上記3つのどれか）
2. この `PROJECT_RULES.md`
3. **`.agents/STATE.md`** — 今どこにいるか（毎セッション必読）
4. `docs/app-specification.md` — 仕様書。機能・データ構造・決定済み仕様
5. 変更対象に対応する正典文書（§9 文書マップ）

## 1. 役割憲章

エージェントは**能力も費用も違います。得意なことだけをやらせる**のがこの憲章の目的です。

> ### この体制の前提（ユーザー決定・2026-08-21）
>
> **開発者はますださん1人で、常時使っているのは Claude Code だけです。**
> Codex と Antigravity は「必要なら開く」もので、**常駐していません。**
>
> したがって **Claude Code は3役すべてを兼ねます。** 実装も実機検証も自分で行ってよく、
> 「これは Codex の担当だから」と止まらないでください。**止まるとユーザーの手が塞がります。**
>
> Codex / Antigravity へ渡すのは、**渡した方が明らかに得なときだけ**です ——
> 長時間の実装をローカルで回したい、独立した目でレビューさせたい、費用を抑えたい、など。
> 渡すときは §3 の書式に従います。
>
> **役割を分けている理由は「誰がやるか」ではなく「どのモードで作業しているか」です。**
> 進行管理モードで作業しているときにコードを書き始めると、検証する人がいなくなります。
> モードを切り替えるときは、切り替えたことを明示してください。

### Claude Code — 全役を兼ねる（既定の担当）

- **設計・進行管理**: 何を、どの順でやるかの設計。作業プロンプトの作成。**報告の検証**。
  アーキテクチャ・方針の検討、ユーザーとの作戦会議、全体レビュー、叩き台づくり
- **実装・レビュー**: 実装、`npm run build` / `npm run test:dataloss`、差分の取りまとめ、
  深掘りのコードレビュー（指摘の作法は下の Codex の節と同じ）
- **実機検証・外部環境**: adb 操作、プロキシワーカーと Ollama の起動・疎通確認、
  Firestore の状態確認。**§6 の鉄則を必ず読んでから触ること**
- **マージは実行してよい**（ユーザー決定・2026-08-21）。条件は下の「誰も勝手にやらないこと」

**進行管理モードに徹すると宣言したセッション中は、コードを書かず・adb を触りません。**
指示と検証に徹します。それ以外のときは、上の3つをすべて自分でやってかまいません。

### Codex — 実装とコードレビュー（必要なときに開く）

- 実装、ローカル検証（`npm run build` / `npm run test:dataloss`）、差分の取りまとめ
- **深掘りのコードレビュー。** 指摘には必ず**該当ファイルの行番号**と、
  **それが壊れる具体的な入力または状況**を添える。
  「〜した方がよい」だけの指摘は、受け取る側が真偽を確認できないため採用されない
- 確信が持てないものは「**確信度: 低**」と明記して出す。落とすより、確信度つきで出す方がよい
- **adb を実行しない。プロキシワーカーを起動・停止しない。** 実機やワーカーの状態が必要な調査に
  行き当たったら、自分で触らず「**何が確認できれば判断できるか**」を書いて止まる
- 指示が誤っていると分かったら、黙って従うのも黙って直すのも誤り。§4-5 に従う

### Antigravity — 実機検証・外部環境（必要なときに開く）

- 実機QA（adb 操作）、プロキシワーカーと Ollama の起動・疎通確認、Firestore の状態確認、
  観測結果の記録
- 加えて、軽い壁打ち・進捗の確認・次のプロンプトの起草補助（費用が安いため、この用途に向く）
- **本体コード（`src/` と `proxy/index.js`）を変更しない。**
  作ってよいのは `src/` の外に置く検証用スクリプトだけ。
  **検証を通すための本体コード変更（テスト用バイパス・ログ追加・しきい値の緩和）は、
  どんなに軽微でも行わない。** 足りないものは「何が足りないか」を Codex へ報告する
- 判定は「実際に動かして観測した事実」に基づく。未実施を推測で PASS と書かない

> **Antigravity の出力の扱い**: 壁打ちや要約は参考情報であり、**判断の根拠にはしません**。
> 進捗の正は `.agents/STATE.md` と、Claude Code の検証を通った報告です。

### 進行管理モードの出力形式

進行管理を担当するセッションは、**毎回の返答の最後にロードマップの表を出します。**
ユーザーが知りたいのは「**自分が次に何をするか**」であって、経緯の要約ではありません。

| 列 | 中身 |
|---|---|
| # | 通し番号。**終わったものは打ち消し線にして残す**（消さない。消すと進んだ実感が消える） |
| やること | 一行。名詞で終える |
| 担当 | Claude / Codex / Antigravity / **あなた**（＝ユーザー） |
| 外部環境 | 実機・ワーカー・Firestore が要るなら「必要」。不要なら空欄 |

加えて次を守ります。

- **ユーザーの作業だけを「あなたがやること」として表の前に別出しする。** 番号を振り、
  貼るだけのプロンプトはコードブロックにする。ユーザーに探させない
- **作業プロンプトの起草に、毎回の許可を取らない。** 必要になったらそのまま起草して出す。
  **確認を求めるのは「ユーザーの判断が要るもの」だけ** ——
  設計方針の二択、正典（`docs/app-specification.md` / この文書）を変える提案、
  範囲の切り方で結果が変わる判断、ユーザーが読む文言（UI・通知）。
  **「決定を仰ぐ」と「作業を始める許可を取る」は別物で、後者は不要**
- **いま止まっている原因を1行で書く。** 誰の返事待ちか、何が終わっていないか
- 表の外に長い解説を積まない。判断材料は聞かれてから出す

### 誰も勝手にやらないこと

- **既存のユーザーデータの編集と削除。** 実機に入っている本人のジャーナル・ToDo・ルーチン・
  AIチャット履歴、エクスポート済みJSON。**端末内にしか無く、クラウド同期は無い**（§7）ので、
  消したら戻りません。2026-07-30 に実際に全消失させています（§8）
- **本番相当データの削除。** Firestore の `ai_requests`、`android/app/evjou.keystore`、
  `android/keystore.properties`、`proxy/serviceAccountKey.json`。
  keystore は**失っても漏らしても復旧不能**（`docs/operations.md` §8）
- **指示書に書かれていない環境設定の変更。** 実機の設定、`proxy/.env`、Firestore のルール、
  IME の戻し忘れ、`vite.config.js` の `build.target`
- **未検証のままのマージと、履歴の書き換え。**
  マージ自体は Claude Code（進行管理役）が実行してよい（ユーザー決定・2026-08-21）。
  ただし**マージ前に `npm run build` が通っていることを確認すること。**
  `git push --force`、公開済み履歴の書き換え、ブランチの削除は**ユーザーに確認してから**行う

## 2. コンテキストの共有 — `.agents/STATE.md`

**エージェント同士はチャットの文脈を共有できません。共有できるのはリポジトリの中身だけです。**
そのために `.agents/STATE.md`（状態盤）を置きます。入口ファイルからこの正典を経由して
必ず読まれる位置にあるので、どのツールで始めても同じ現在地から出発できます。

**全エージェントの義務:**

1. **セッション開始時に `.agents/STATE.md` を読む。**
   **ここに書かれていないことは「まだ起きていない」と扱う**
2. **区切りがついたら `.agents/STATE.md` を更新する。**
   対象コミットハッシュ、ブランチの扱い、既知バグ、保留中の決定、次にやること
3. **チャットにしか無い結論を残さない。** 決まったことは STATE.md か正典文書へ書く。
   **チャットに閉じた決定は、次のセッションから見ると存在しないのと同じです**
4. **未了を示す事実を、状態の更新で消さない。**
   「未着手」「未発注」「未検証」「保留」は、進捗を書き換えるときに真っ先に消えます。
   **消すのは、それが実際に完了した時だけ。**
   次の一手を書き換えるなら「次は X（**未発注**）」のように、
   誰にも渡していないことが読み取れる形にすること
5. **STATE は「追記」で更新する。既存のブロックを置換しない。**
   自分が書く分を足すだけなら事故は起きません。
   見出しや表を作り直すときは、**保存前に `git diff` の `-` 行を自分で読むこと**
6. **古いコードツリーの在り処を明示する。** worktree / ブランチが複数あるとき、
   どれが本体コードの最新でどれが古いかを STATE.md に書く。
   特に**古いツリーで作業を始めると「直したはずの修正が1件も入っていない木」を見ることになります**

## 3. 仕事を渡すときの書式

**エージェントは前提を補完しません。渡さなかった前提は、その場で発明されます。**
別のセッションへ仕事を渡すときは、次を必ず書きます。

| 項目 | なぜ要るか |
|---|---|
| 対象ブランチとコミットハッシュ | どの木を見ているかが食い違うと、報告が噛み合わない |
| ゴール（何が終われば完了か） | 「終わった」の定義は**渡す側が決める。受け取る側に決めさせない** |
| やってはいけないこと | **禁止は明示しないと守られない**（コミット・マージ・adb・本体コード変更 等） |
| 判断に迷ったときの行動 | 既定は「**止まって報告**」。勝手に進めさせない |
| 参照すべき正典文書 | **手順を依頼文に書き写さない。** 文書を指し、そこへ結果を書き戻させる |

手順を依頼プロンプトに丸ごと書く運用はしません。手順がチャットに閉じると、
次のセッションが「何を見たか」ではなく「**何を見なかったか**」を復元できなくなります。

### コード修正を発注するときの完了条件

1. **`npm run build` が通ること。** 大きな一括書き換えは過去にパーサエラーを起こしています。
   小さく変えて都度ビルド検証する
2. **`src/features/useJournal.js`（ジャーナルの保存経路）に触れたら
   `npm run test:dataloss` を通し、実出力を報告に貼る。** これは生命線です（§5）
3. **今回の範囲以外を直さない。** ついでの修正はレビュー中の行番号をずらします
4. **ユーザーに見える挙動・文言を変えたら、実物を報告にそのまま貼る。**
   文言は最終的にユーザーが判断します
5. **仕様を変えたら `docs/app-specification.md` を同じ差分で更新する。**
   文書を別作業へ切り出すと必ず腐ります（§8 に実例あり）

## 4. 報告と証拠の原則（全エージェント共通）

1. **一次情報を添える。** 行番号、コミットハッシュ、コマンドの実出力、スクリーンショット。
   「たぶん」「〜のはず」は結論ではなく、確信度つきの仮説として書く
2. **実出力は打ち直さない。コピーして貼る。**
   「貼った証拠」と「書いた記憶」は読む側から区別できません。
   区別できない証拠は証拠として使えず、**捏造と同じ扱いになります。**
   長すぎるなら省略記号で切って「切った」と書く。要約して置き換えない
3. **事実と推定を分ける。** 推定には「推定:」と明示する
4. **やっていないことを「やった」と書かない。** 未実施は「未実施」と書けば十分。
   **これは減点ではありません。捏造だけが減点です**
5. **指示が誤っていると分かったら、逸脱する前に申告する。**
   何が誤りで、なぜそう判断したかを（できれば実証して）示し、より良い案を提案してから進める
6. **同じ場所で3回失敗したら止まって報告する。** 4回目を試さない

## 5. ビルドとテスト

```bash
npm install
npm run dev            # 開発サーバ（Vite / port 5173）
npm run build          # 本番ビルド。リファクタ後は必ず通す
npm run test:dataloss  # 手入力消失対策の実機ブラウザ回帰テスト（生命線）
```

- `test:dataloss` は `vite build` の後に `node e2e/dataloss.cjs` を実行し、Playwright で
  **自動保存(800ms) / 日付切替フラッシュ / リロード保険(beforeunload) / レガシー移行**を検証します。
  **`src/features/useJournal.js` を触ったら必ず通すこと。**
- ブラウザが別管理の環境では `PLAYWRIGHT_CHROMIUM=<chromiumパス>` を渡します
- **CI はありません。** 検証はローカルで走らせた人が結果を貼る以外に経路がありません
- プロキシワーカーの起動・停止・疎通確認は `docs/operations.md` §2〜§3。
  **`proxy/index.js` を触ったら、ワーカーを再起動してから疎通確認まで通すこと**

## 6. 環境の罠（実際に踏んだもの）

- **PowerShell 5.1 では `&&` / `||` が使えません**（パーサエラーになる）。
  条件付き連結は `A; if ($?) { B }`、無条件連結は `A; B`
- **PowerShell 5.1 の `Set-Content` / `Add-Content` は既定が ANSI コードページ**で、
  日本語ファイルを文字化けさせます。`-Encoding utf8` を明示するか、
  **ファイルの読み書きはエージェントのファイル編集ツールで行うこと**
- **Git Bash から adb を使うときは `export MSYS_NO_PATHCONV=1` が必要。**
  無いと `/sdcard/...` が `C:/Program Files/Git/sdcard/...` に化けます
- **`npm run build` が出す「chunks are larger than 500 kB」警告は無害です**
  （`dist/assets/index-*.js` が約 920kB）。これを消すために `vite.config.js` を触らないこと
- **`vite.config.js` の `build.target: ['es2015', 'chrome74']` を外さない。**
  OPPO Reno A（ColorOS・Chrome 74 相当の WebView）では、Optional Chaining（`?.`）や
  Nullish Coalescing（`??`）がトランスパイルされずに出ると**起動時にクラッシュします**

### 実機に日本語を入力する（Mi 10 Pro / adb serial `a5f1d85` / Android 13）

手段は **ADBKeyBoard IME のみ**です（2026-07-30 に確立）。
`cmd clipboard set-text` は Android 13 では "No shell command implementation" となり使えません。

- APK は ADBKeyBoard（端末に導入済みのものは `versionCode=2` / `versionName=2.0`）

> **★ 訂正（2026-08-21・実機で再現を試みて確定）**
>
> ここにはかつて「**`adb install` は `-t` が必須。無いと `INSTALL_FAILED_USER_RESTRICTED` が返る。
> 実際は debug ビルドを弾かれているだけで、MIUI のセキュリティ制限と誤認する**」と
> 書かれていましたが、**これは誤りでした。**
>
> 端末から APK を取り出して `aapt2 dump xmltree` で調べたところ、
> **`android:testOnly` 属性は存在しません**（あるのは `android:debuggable=true` だけ）。
> `-t` は `testOnly="true"` の APK を許可するフラグなので、**この APK には最初から無関係**です。
> 実際に `adb -s a5f1d85 install -r`（`-t` なし）で `Success` しました。
>
> したがって `INSTALL_FAILED_USER_RESTRICTED` は**額面どおり MIUI 側の制限**です
> （「USB経由でインストール」の設定 / Mi アカウント要求）。
> 当時 `-t` を足したのと制限が解けたのが同時期だったため、**因果を取り違えたと推定されます。**
>
> **教訓: エラーコードを「実際は別の原因」と読み替えるときは、読み替えの根拠を残すこと。**
> 根拠のない読み替えは、後から検証できない誤情報として残ります（§4-3）。
- 有効化: `adb shell ime enable com.android.adbkeyboard/.AdbIME` → 同じ引数で `ime set`
- 入力: `adb shell am broadcast -a ADB_INPUT_TEXT --es msg <文字列>` / 全消去は `-a ADB_CLEAR_TEXT`
- **撮影後に IME を戻すこと**:
  `com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME`

落とし穴:

1. **半角スペースを含む文字列は壊れます**（`adb shell` が引数を再分割するため）。
   シングルクォートで包んだ上でさらにダブルクォートで包み、二重にクォートすること
2. **改行は送れません。** 1行ずつ送り、間に `input keyevent KEYCODE_ENTER` を挟む
3. **MIUI の電卓がフリーフォームで前面に残り、タップと入力を奪うことがあります**

### 実機を操作するときの鉄則

> ### ★★ adb には複数の端末が同時に接続されています（2026-08-21 実測）
>
> **`-s <シリアル>` を付けない adb コマンドを実行しないでください。**
> シリアルを省くと adb は「接続が1台だけ」の想定で動き、複数台あるときは
> `error: more than one device` で止まるか、**意図しない端末に当たります。**
>
> | シリアル | 端末 | 用途 |
> |---|---|---|
> | `a5f1d85` | Xiaomi Mi 10 Pro（`cmi`・Android 13） | EvJou の主検証機。**ユーザー本人の実データが入っている** |
> | `1d05e7bc` | OPPO Reno A（`CPH1983`・ColorOS） | 旧WebView（Chrome 74 相当）の互換確認用 |
> | `R5CT43R8P0D` | Samsung `SCG13`（Galaxy S22・au） | **EvJou とは無関係の可能性が高い。触らないこと** |
>
> **どの端末に何が入っているか確信が持てないときは、書き込み操作をせずに報告してください。**

- **タップの前に必ず `screencap` と `dumpsys window | grep mCurrentFocus` で対象を確認する。**
  これを怠って 2026-07-30 にアプリを誤アンインストールし、実機のデータを全消失させています（§8）
- **アンインストールと「データを消去」を実行しない。**
  APK の入れ替えは `adb install -r`（上書き）で行う。`adb uninstall` は
  **ユーザーに確認してから**でなければ実行しない。EvJou のデータは端末内にしか無く、
  クラウド同期がないため、消したら戻りません
- **スワイプを画面上端から始めない**（通知シェードが降りてくる）
- **端末とビルドの同一性を最初に固定する。** どのコミットをビルドして入れ、どの端末で実施したかを
  結果に含める

## 7. このプロジェクトの設計上の制約（触ると壊れるもの）

- **タイムゾーン**: 日付は必ず `toLocalDateStr()`（ローカル基準）を使う。
  **`toISOString()`（UTC）は使わない。** 日付の境界が 09:00 JST にずれます
- **ストレージ**: 保存先は `src/storage/` のアダプタに閉じ込めてあります。
  UI・ロジックは保存先の実体を知りません。**生の `window.storage` を追加しないこと**
  （Claude.ai アーティファクト専用APIで、通常環境には存在しません）
- **データはすべて端末内。** Android は IndexedDB ＋ Capacitor Preferences への二重書きで、
  読み出しは IndexedDB → Preferences → localStorage の順にフォールバックします。
  **クラウド同期は無いので、端末を初期化するとデータは消えます**
- **ジャーナルのコアフィールド**: `CORE_FIELD_KEYS`（`todayGoal` / `tomorrowGoal`・
  `src/constants.js:14`）はリネームと並べ替えはできますが、**削除できません**。
  ToDo抽出・スケジュール生成・AIチャットの文脈がキーで読むためです。
  フィールドを消してもデータは消えず、戻せば過去の記録が再び見えます
- **AIの中継に Firestore を使う理由を忘れない。** スマホから自宅PCのローカルLLMへ届けるのに、
  **ポートを開けずに NAT を越える**ためです。副産物として API 課金がゼロで、
  推論内容が外部の推論事業者に渡りません。**「HTTP で直接繋げばよい」に戻さないこと。**
  経路の全体像と起動手順は `docs/operations.md` §1〜§2
- **AIリクエストのキュー契約を「単純化」しない。**
  ワーカーは要求を見た瞬間に**受理**し（`pending` → `queued` + `queuePosition`）、
  ジョブが1つ捌けるたびに `queuePosition` を書き直します。
  したがってクライアントは**経過時間ではなく「沈黙」を測ります**
  （受理が60秒無い＝ワーカー不在／受理後180秒 文書更新が無い＝停滞／600秒 絶対上限）。
  **これを単一の固定タイムアウトへ戻すと、それがこの実装が潰したバグそのものです**
- **AIタスクを1プロンプトにまとめない。** 要求数を節約するために要約とToDo抽出を
  1回にまとめると品質が落ちます。ローカルLLMなので API 課金はありません
- **スクリーンショット撮影のために `src/` を書き換えない。**
  アプリは別ブランチで開発が進んでおり、撮影用の細工はマージ衝突を起こします。
  特定の画面状態が要るなら、**ユーザーに手で入力・遷移してもらうこと**
- **AI推論経路の配布方法は未決着です。** `callCloud()` は Anthropic API をブラウザから直叩きし、
  アーティファクト環境ではキーが自動注入されていましたが、通常環境では認証が通りません。
  配布時の経路（BYOK / オンデバイス小型LLM）は**このプロジェクト最大の未決論点**です
- **再提案禁止の一覧が `docs/user-context.md` にあります。**
  恒久的に不採用のもの（ホーム画面追加 / ToDoの繰り返し / 目標の履歴保持 / ハンバーガーメニュー /
  企業向け展開 / エラーログ解析タブ / インアプリ疑似通知 等）と、
  v1スコープ外のもの（OS通知・リマインダー / 検索機能 / 古いデータの自動要約）は**別の扱い**です。
  後者は否定ではなく、v1リリース後なら再検討できます。**提案する前に必ず該当表を見ること**

### 設計の方向（リファクタリングの目標）

Microsoft To Do / Google ToDo のような**ローカルファースト設計**。将来 Firebase/Supabase で
アカウント同期。まずはオフライン完結の堅牢な基盤を作ります。3層分離を進めます。

1. **UI層**（`src/components/`）— 状態を持たない表示コンポーネント
2. **ロジック層**（`src/lib/`, `src/api/`, `src/features/` のフック）— 状態管理・ドメインルール・AI通信
3. **ストレージ層**（`src/storage/`）— 保存先を抽象化。`localStorage` → IndexedDB / クラウドDB へ
   アダプタ差し替えで対応。UI・ロジックは保存先の実体を知らない

`src/components/ErrorBoundary.jsx` が画面全体のクラッシュを防いでいます。
